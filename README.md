# Gemini Gateway for macOS

[![macOS build and tests](https://github.com/bdgdnl/gemini-gateway-macos/actions/workflows/ci.yml/badge.svg)](https://github.com/bdgdnl/gemini-gateway-macos/actions/workflows/ci.yml)

Нативный лаунчер и локальный API-шлюз для **Antigravity Desktop и Antigravity IDE**. Работает через **Happ / HTTP / SOCKS5, AmneziaWG или другой системный VPN**.

Gateway написан на Swift/AppKit. Исходники и процесс сборки опубликованы целиком. Приложение не использует серверы автора и не включает файлы Antigravity, VPN-конфигурации или чужие исполняемые модули.

**Требования:** Apple Silicon (M1 и новее), macOS 13+, установленный Antigravity Desktop и/или IDE. Для готового приложения Python, Node.js и Rust не требуются.

## Установка

Скачайте `Gemini-Gateway-macOS-arm64.zip` из [Releases](https://github.com/bdgdnl/gemini-gateway-macos/releases), распакуйте и откройте **Gemini Gateway.app**. Если готового релиза ещё нет, используйте сборку из исходников ниже.

Приложение имеет **ad hoc-подпись**, без Developer ID и нотариализации Apple. При первом открытии macOS может предложить разрешить запуск через «Системные настройки → Конфиденциальность и безопасность». Глобально отключать Gatekeeper или SIP не требуется.

Для проверки целостности скачайте `SHA256SUMS` из того же релиза:

```sh
shasum -a 256 -c SHA256SUMS
```

Совпадение хеша подтверждает целостность файла, а не отсутствие уязвимостей.

## Быстрый старт

1. Подключите нужный VPN или прокси.
2. Откройте Gateway и выберите **маршрут**.
3. Нажмите **«Проверить маршрут» → «Применить маршрут»**.
4. Нажмите **«Открыть Desktop»** или **«Открыть IDE»**. Можно использовать оба клиента.
5. При первом запуске войдите в Google в отдельном профиле и отправьте сообщение Gemini.

Крестик скрывает окно Gateway; шлюз продолжает работать в строке меню. Полный выход доступен через меню. После остановки шлюза соединения клиентов закрываются. Обычный значок Antigravity запускает обычное приложение; для локального API-релея запускайте клиент кнопкой Gateway.

### Happ / HTTP / SOCKS5

Включите подключение в Happ и нажмите **«Найти Happ»**. Обычные адреса — `socks5://127.0.0.1:10808` и `http://127.0.0.1:10809`. Можно ввести адрес другого HTTP/SOCKS5-прокси вручную. Логин/пароль в адресе пока не поддерживаются. Для SOCKS5 имена назначения разрешаются через прокси.

### AmneziaWG

1. Откройте AmneziaWG и подключите заранее настроенный туннель.
2. Выберите **AmneziaWG** в Gateway.
3. Нажмите **«Проверить маршрут» → «Применить маршрут»**.

Gateway определяет активное подключение через macOS и привязывает исходящие API- и CONNECT-соединения к его `utun`-интерфейсу. При отключённом туннеле новые запросы отклоняются; переход на обычное подключение автоматически не выполняется. Системный DNS остаётся под управлением macOS и VPN-клиента.

Happ в этом режиме не требуется. Gateway не импортирует ключи, не изменяет конфигурацию и не включает/выключает туннель. Сам AmneziaWG может направлять трафик всего Mac согласно вашей VPN-конфигурации.

### Другой системный VPN

Этот режим использует текущие маршруты macOS без локального прокси и без привязки к конкретному VPN-интерфейсу. Сначала подключите свой VPN. Для AmneziaWG используйте отдельный пункт **AmneziaWG**.

### Смена маршрута и перезапуск

Выберите подключение и нажмите **«Применить маршрут»**. Клиент закрывать не требуется, но текущий запрос может прерваться — повторите его.

Gateway сохраняет выбранный локальный адрес и восстанавливает соединение с оставшимся открытым клиентом после своего перезапуска. Если вы явно нажали «Остановить шлюз», автоматическое восстановление отключается до следующего запуска клиента кнопкой.

## Как устроена работа

```text
Antigravity → локальный API-релей → выбранный прокси / VPN → HTTPS Google
```

API-релей обрабатывает запросы к фиксированному Cloud Code endpoint Google. Другие HTTPS-соединения проходят через локальный CONNECT-прокси без расшифровки. Потоковые ответы генерации передаются по мере получения.

Опция **«Обход региональной проверки клиента»** обрабатывает успешный ответ `loadCodeAssist`: удаляет поля `ineligibleTiers` и при необходимости добавляет описание бесплатного тарифа. Ошибки сервиса, квоты и тарифные ограничения не превращаются в успех. Это не предоставляет платный доступ и не гарантирует доступность сервиса для аккаунта или выходного IP.

### Desktop

Gateway создаёт отдельную копию установленного приложения, меняет только её API-адрес в `lsDefaults.js` внутри ASAR, пересчитывает хеши и подписывает копию ad hoc. Унаследованный карантин снимается **только с этой копии**. Оригинал в `/Applications` не редактируется.

Обновление исходного Desktop приводит к пересозданию копии при следующем запуске через Gateway. Не запускайте подготовленную копию напрямую: сначала должен работать шлюз. Неизвестная структура ASAR приводит к ошибке вместо произвольного патча.

### IDE и авторизация

IDE использует отдельный профиль и настройку `jetski.cloudCodeUrl`. Файлы установленного IDE не патчатся. Профили намеренно не копируют прежнюю авторизацию и настройки.

Вход выполняется через штатный интерфейс Google/Antigravity. На время работы callback браузерной авторизации направляется через Gateway в отдельный профиль; прежний обработчик восстанавливается при остановке/выходе. После аварийного завершения восстановление выполняется при следующем запуске Gateway.

## Конфиденциальность и изменения в системе

API-релей видит API-запросы и заголовки авторизации в памяти, поскольку сам устанавливает исходящее HTTPS-соединение. Его исходники доступны для проверки.

- API слушает только `127.0.0.1`, на сохраняемом случайном порту, со случайным префиксом пути. Проверяются Host и Origin; браузерные cross-site запросы отклоняются.
- TLS-сертификаты Google проверяются системным curl; `--insecure` не используется. Собственный доверенный CA не устанавливается.
- Тела запросов и ответы модели не пишутся в обычные файлы. Для передачи тела в curl используется FIFO в закрытом временном каталоге.
- В журнале находятся статусы, методы и сокращённые имена операций. Query-параметры и идентификаторы ресурсов скрываются; журнал хранится в памяти. Защищённый локальный `/diagnostics` возвращает последние 40 событий.
- Сам Gateway не добавляет телеметрию, автообновления и обращения к серверам автора. Служебные запросы самого Antigravity передаются в Google.
- Прокси-переменные задаются только запускаемым процессам. Системный прокси, hosts, DNS, доверенные сертификаты и глобальные настройки SIP/Gatekeeper не изменяются. Root и автозапуск не требуются.

Локальные файлы находятся в `~/Library/Application Support/Gemini Gateway/`:

| Путь | Назначение |
| --- | --- |
| `Desktop/Antigravity.app` | Отдельная локальная копия Desktop |
| `Desktop Profile/` | Профиль, который использует сам Desktop |
| `IDE Profile/` | Отдельный профиль IDE |
| `session.json` | Локальный адрес, маршрут и параметры восстановления |

Gateway также сохраняет собственные настройки выбора маршрута и восстановления callback в настройках macOS. История и токены, которые хранит официальный клиент в своём профиле или Keychain, остаются ответственностью этого клиента. Gateway не изолирует аккаунт от других приложений с правами вашего пользователя.

## Сборка из исходников

Нужны Apple Silicon и Xcode Command Line Tools со Swift 5.9+:

```sh
git clone https://github.com/bdgdnl/gemini-gateway-macos.git
cd gemini-gateway-macos
bash build.sh
python3 Tests/integration.py
bash scripts/package.sh
```

Результаты: `dist/Gemini Gateway.app`, ZIP-архив и `SHA256SUMS`. Версия берётся из `VERSION`.

Сборка в отдельную папку при работающем локальном Gateway:

```sh
GATEWAY_APP_OUTPUT="$PWD/staging/Gemini Gateway.app" bash build.sh
GATEWAY_TEST_BIN="$PWD/staging/Gemini Gateway.app/Contents/MacOS/GeminiGateway" \
  python3 Tests/integration.py
```

GitHub Actions собирает приложение и запускает loopback-тесты на Apple Silicon. Публикация тега `vMAJOR.MINOR.PATCH`, совпадающего с `VERSION`, запускает сборку релиза с ZIP и SHA-256. В репозитории и релизе находятся только Gateway и его исходники; копия Antigravity, профили и настройки VPN не публикуются.

## Проверки и ограничения

24 интеграционных теста покрывают HTTP/SOCKS5 CONNECT, передачу авторизации и тел, chunked-ввод, потоковую выдачу, REST-методы и HEAD, сохранение HTTP-ошибок, ограничения локального API, восстановление адреса, отсутствие секретов в диагностике, ASAR-хеши, очистку окружения Electron и отказ без VPN-интерфейса. Тесты используют loopback и вымышленные токены; аккаунт Google и реальный VPN им не нужны.

Подготовка Desktop проверялась на версии 2.32.2. Также проверялись открытие окна и запуск Language Server, запросы через Happ/AmneziaWG и ответы служебных API Google. Это не гарантия работы всех версий клиентов, аккаунтов и моделей. Изменение серверных правил или структуры клиента может потребовать доработки.

### HTTP 400: User location is not supported

Это отказ Google по региону подключения. Включённый VPN и успешное TLS-соединение не гарантируют подходящий маршрут: разные домены могут обрабатываться разными правилами, а геолокация IP у Google может отличаться от других сайтов.

Попробуйте другой сервер подключения и проверьте маршрутизацию для `daily-cloudcode-pa.googleapis.com`, `cloudcode-pa.googleapis.com`, `aicode.googleapis.com` и `generativelanguage.googleapis.com`. Причина отказа доступна через **Copy debug info** в клиенте. Gateway сохраняет настоящий статус и ответ сервиса.

### Локальный HTTP 404

Допустимые относительные REST/RPC-пути передаются Google. Недопустимые пути и запросы с неверным локальным адресом отклоняются самим Gateway. В журнале можно отличить локальный отказ от `Google HTTP 404`.

Если отправляете отчёт об ошибке, достаточно версии Gateway, режима подключения, статусов и текста причины. Не публикуйте токены, файлы профилей, `session.json` и VPN-конфигурации.

## Удаление

Завершите запущенные через Gateway клиенты и выйдите из самого Gateway штатным выходом, чтобы восстановить обработчики авторизации. Удалите Gemini Gateway.app. Если созданные профили больше не нужны, удалите `~/Library/Application Support/Gemini Gateway/`. Данные в этих отдельных профилях также будут удалены.
